### What changed since the baseline

Two fixes, one run each; sampling noise is real (one answerable question = 2.8 pp,
one unanswerable question = 7.1 pp).

**1. Measurement fix — not a system improvement** (`fix(eval)`, 95c1fea). The key-fact
check now reads 12-hour time, so "10:00 AM to 8:00 PM" matches the fact "20". It changes
only the score of the baseline's own answers: a34 was correct all along. Effect: answer
accuracy 72.2% → 75.0% (the "Δ measurement" column). Nothing the system outputs changed.

**2. System fix** (`fix(rag_core)`, dc077b1). `gpt-oss-120b` often writes citations as
`【1】`; rag_core recognised only `[1]` and discarded those answers as uncited. 8 of the 9
baseline false refusals were correct answers lost this way (the 9th, a03, is a retrieval
miss). After normalising the markers: false refusals 25.0% → 2.8% (only a03 is left),
NO_ANSWER precision 60.9% → 92.9%, answer accuracy 75.0% → 91.7%.

**Side effects and noise, not caused by the fixes:**

- *Hallucination rate 0% → 7.1% (1 of 14).* n13 "Can I pay with Bitcoin?" was refused by
  the model itself in the baseline; this run it answered "No, Bitcoin is not listed as an
  accepted payment method … [1]", inferred from the payment methods and "currency: Kyrgyz
  som only". By the benchmark label it is a hallucination; the label is arguably too strict.
  Kept as is: labels are not changed after seeing results.
- *Citation validity 100% → 94.4%.* Two English answers now get through (a35, n13); they
  cite Russian passages, which the lexical check cannot verify ("cross-language"). No
  citation was found invalid.
- *Latency p95 1247 → 3927 ms.* Provider response-time variance; the fix is a regex on the
  reply and adds no requests.

**Still open (measurement):** a07 and a12 are correct answers that fail over-strict key
facts ("30" vs "30 000", the word stem "космет"). Not changed in this round.

**Still open (system):** a03 "Если я закажу в 12 часов дня, когда привезут?" — the delivery
document is not retrieved; a known retrieval weakness.
